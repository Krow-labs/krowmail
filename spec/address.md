# 地址语法

本文件是地址的唯一事实来源。实现以 `spec/test-vectors/` 为准，规范与向量冲突时先改规范再改代码。

## 形式

友好地址写作：

```text
段#段#段@域名
```

本地部分有 1 到 3 段，段之间用 `#`。从右往左读：最右一段是本域名里的最外层标识，向左是更内层。段数由该域名在根节点登记，不由发件人自选。`krow.cn` 登记为 3 段，顺序是 `组员#小组#主人@krow.cn`。

只有一段时没有 `#`。两段是 `内层#外层@域名`。

域名只比较 `@` 右侧。根节点不接收 `@` 左侧。

## 归一化

比较前对每一段做折叠，规则与测试向量一致：

1. 遇到零宽字符（U+200B、U+200C、U+200D、U+FEFF、U+2060）或双向控制字符（U+202A–U+202E、U+2066–U+2069），整段拒绝。
2. 全角 ASCII（U+FF01–U+FF5E）减去 0xFEE0 变成半角。
3. 表意空格 U+3000 变成普通空格。
4. 去掉首尾空白，再做 Unicode 小写。

地址名（给人起的名字，不是自动编号）另有限制：折叠后 1 到 32 个字符；不能是纯数字；只能是字母、数字、中文以及 `_` `.` `-`。主人段若是名字，还不能使用保留字：`krow`、`admin`、`administrator`、`support`、`root`、`system`、`mail`、`postmaster`、`abuse`、`security`、`official`、`noreply`、`hostmaster`、`webmaster`。纯数字段是自动编号，不走地址名规则。

展示名里禁止 `@`、`#` 以及它们的全角形式。

## URI

名片和链接使用 `krowmail:` 方案。`#` 在 URI 里是片段分隔符，必须写成 `%23`。

```text
krowmail:大风%23PST%23道哥@krow.cn
```

解析时仍接受人手输入的 `mailto:` 前缀和尖括号包裹。`mailto:` 只作为输入兼容，不是本协议的方案。

## 不在本规范内

`krow:<uuid>/<uuid>/<uuid>` 是 `krow.cn` 的本地扩展，用于已经发出去的旧信。其它域名不必实现。向量放在 `spec/test-vectors/address.json` 的 `profile=krow.cn-local` 条目里，互操作测试可以跳过它们。
